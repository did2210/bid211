## Что было не обеспечено изначально

Рабочая заметка, а не инструкция. Инструкция появится, когда будет выбран
способ установки. Здесь — список мест, где разработка на домашней машине
расходится с боевым сервером. Каждое из них ломает перенос молча.

## Что есть на сервере

`GFDDBScandata`, `10.0.0.112`, Ubuntu 24.04, 8 ядер, 62 ГБ RAM, диск
`/mnt/gfd_data` — 1 ТБ, свободно 611 ГБ. PostgreSQL 16.14 с боевой
`gfd_database_scandata`. Из софта — **только `python3` и `git`**.

**Ни ClickHouse, ни Docker, ни Node.** При этом спека обещает перенос
командой `docker compose up -d` — обещание ничем не обеспечено.

Открыт доступ к репозиториям Ubuntu и к `packages.clickhouse.com`
(проверено). То есть возможны оба пути: поставить Docker пакетом либо
поставить ClickHouse пакетом и обойтись без Docker.

## Решение: ставим Docker (Матвей, 2026-08-08)

Витрина и служебная база едут контейнерами, боевой PostgreSQL остаётся
как есть — от него нужен только сетевой доступ на чтение. Среда сервера
совпадает с той, где всё писалось и проверялось, а дальше по стеку
(FastAPI, nginx, статика веб-приложения) добавляются тем же способом.

Пошаговый порядок установки — `docs/установка-на-сервере.md`.
Серверные отличия конфигурации — `docker-compose.server.yml`.

## Что сломается при переносе прямо сейчас

1. **Пользователь ClickHouse `gfd` создаётся docker-энтрипоинтом** через
   переменные `CLICKHOUSE_USER` / `CLICKHOUSE_PASSWORD`. При установке
   пакетом энтрипоинта нет — пользователя тоже. Нужен файл в `users.d`,
   собираемый из `.env` при развёртывании (в git пароль класть нельзя).

2. **Init-скрипты PostgreSQL выполняются только на пустом томе.**
   `pg_app/init/01_journal.sql` (таблица `client_map` с правилами
   переименования сетей) на уже развёрнутой базе не применится. Миграции
   служебной базы должны выполняться кодом.

3. **Адрес PostgreSQL для словарей.** `DICT_SOURCE_HOST` / `DICT_APP_HOST`
   локально указывают на имена сервисов docker-сети. На сервере это адрес
   машины с боевой базой — при установке пакетом `localhost:5432`.

4. **Порты биндятся на `0.0.0.0`.** На `10.0.0.112` витрина и служебная база
   окажутся видны всей внутренней сети. Нужен `127.0.0.1`.

5. **Нет `restart: unless-stopped`** — после перезагрузки сервера ничего
   не поднимется само. При установке пакетом ту же роль играет systemd.

6. **Нативный порт ClickHouse `9000:9000` захардкожен** мимо переменных.

## Что проверить на сервере первым делом

- `SELECT DISTINCT client FROM sales` в боевой базе — сверить написание
  исключаемых сетей с `EXCLUDED_CHAINS`. Фильтр сравнивает названия как
  текст: «ПЯТЁРОЧКА РЦ» через «Е» не отсеет ничего и промолчит.
- Доступ к GitHub с сервера: `curl -sI https://github.com | head -1`.
  Закрыт — код поедет файлообменником.
- Свободное место под витрину и число партиций при заливке всей истории.
